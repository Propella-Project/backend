Authentication

This project uses JWT authentication via djangorestframework_simplejwt.

Obtain an access token by POSTing credentials to /api/accounts/token/. Include the token in subsequent requests:

Authorization: Bearer <access_token>

Interactive Login / Logout

Purpose: Quick browser-based login that stores the access token in localStorage and demonstrates using it for authenticated requests.

Try it: open /templates/login.html (or copy the template into a served page) and use the form to authenticate.

How it works (JS snippet)

// POST credentials to obtain token
fetch('/api/accounts/token/', {
  method: 'POST',
  headers: {'Content-Type': 'application/json', 'Accept': 'application/json'},
  body: JSON.stringify({email: 'you@example.com', password: 'password'})
}).then(r=>r.json()).then(data => {
  localStorage.setItem('access_token', data.access);
});

// Use token for requests
fetch('/api/accounts/all-users/', {
  headers: { 'Authorization': 'Bearer ' + localStorage.getItem('access_token') }
}).then(r=>r.json()).then(console.log);

Login / Logout toggle

The minimal toggle logic used by the documentation page:

if(localStorage.getItem('access_token')){
  // show logout button
} else {
  // show login form
}

// to logout:
localStorage.removeItem('access_token');

Note: the interactive widget in the template uses AJAX (fetch) and stores the token in localStorage. For production clients prefer secure httpOnly cookies or a more secure storage pattern.

GET /api/accounts/all-users/

Purpose: Return a list of all users.

Auth: Required — JWT access token. Additionally the view enforces a role check: the requesting user must have role == 'admin'.

Success response (200)

[
  {"id":1,"username":"alice","email":"alice@example.com"},
  {"id":2,"username":"bob","email":"bob@example.com"}
]

Error responses

{"detail":"Authentication credentials were not provided."}  // 401 if token missing/invalid
{"error":"Unauthorized"}  // 403 if authenticated but not admin

Common Response Codes

  • 200 — OK
  • 201 — Created
  • 400 — Bad Request / validation error
  • 401 — Unauthorized (missing/invalid token)
  • 403 — Forbidden (authenticated but not permitted)
  • 404 — Not Found

Tips for Postman

  • Set Accept: application/json in headers to avoid large HTML browsable API responses.
  • Add Authorization: Bearer <access_token> for protected endpoints.
  • To test admin-only endpoints, create a user with role='admin' or update the DB directly.
  • Import OpenAPI spec into Postman: Download the spec from /api/schema/ and use Import → Link to auto-generate all endpoints with proper auth headers.
